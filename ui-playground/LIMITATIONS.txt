Prototype boundaries — 2026-11-01

IDENTITY (deliberately absent)
There is no persistent entity-ID system. Diffing uses name/position/settings and
unambiguous geometric moves. Blueprint/Things indices are local serialization
indices, not durable identity. Ambiguous moves can appear as add + delete.

COMMITS AND OVERRIDES
Basic geometric World patches ARE captured and reapplied when affected cells
rebuild. It would be inaccurate to say overrides are entirely unimplemented.
However, this is not identity-aware rebasing: if an upstream commit moves, replaces,
or removes an overridden source, there is no complete conflict-resolution model.
Ownership of additions is approximated by footprints/nearest reference. Overlaps
and nested references can be ambiguous. Slot patch routing/reset/stitch exists,
but arbitrary multi-level nested ownership is not solved. Whole-neighbor stitching
back into multiple source templates is not implemented. Wire-only changes have no
separate review rows. Generated scanner/filter/Cybersyn behavior is intentionally
excluded from normal user-change comparison; cooperative user metadata is handled.

REBUILDING
Unchanged World cells retain their entities. Changed cells and changed outside
extensions are still reconstructed from snapshots; live inventory, machine state,
trains, and entity identity are not preserved as production-grade semantics.
The saved single-writer queue spreads work over ticks, but an individual native
capture/blueprint layer can still spike. This is not an entity-level incremental
patch engine or a production-scale performance guarantee.

AUTHORING
Use real entities placed directly in the native template editor, not ordinary
blueprint ghosts, for reliable authoring/change-review tests. Preview ghosts live
on an isolated force and are excluded from commits. The normal Fabric free-placement
cursor is supported; it should not be confused with arbitrary blueprint import.
Snapshots omit rolling stock and the default editor concrete floor. Exotic entity
transforms and isolated elevated rails are not exhaustively covered.

SLOTS
One level: a filler cannot contain slots, including through nested references.
Anchor matching is geometric and type-based; real composition uses committed
anchors. Moving/deleting an anchor requires selecting it again. Author previews
can use a currently selected real anchor before commit; that does not activate
production slot composition. The starter intentionally has no anchors or fillers
configured, so empty picker choices before setup are expected.

OTHER OPEN AREAS
- No version-history browser, per-instance version pinning, or rollback UI.
- No comprehensive upstream-update/conflict warning and reconciliation workflow.
- Fixed 160 x 160 World lattice; custom template dimensions/padding are supported.
- Neighbor ownership clips by entity center; complex rail overlap previews use
  approximate collision geometry. Fine-grained neighbor workflows remain limited.
- No certification of train operations, throughput, multiplayer concurrency,
  robot/undo identity, or large production saves. Test on the disposable starter.

EVIDENCE
Real Factorio integration tests exercise the GUI handlers, snapshot commits,
slots/anchors, staged Apply, hover previews, patch routing, unchanged-cell
preservation, save/reload, cleanup, and live tuning. Scripted handler tests are not
proof of every physical mouse interaction or every gameplay edge case.
