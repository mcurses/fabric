Functional prototype limits — updated 2026-11-01

- No persistent entity identity. Changes are compared geometrically: same-position
  replacements/settings, unambiguous equal-settings moves, otherwise add/delete.
  Ambiguous moves can appear as an addition and a deletion. Blueprint and Things
  IDs are local serialization indices only.
- Template commit still replaces the own snapshot and committed references, then
  rebuilds usages. World entities and running inventory/machine state can be
  recreated. Geometric world patches are retained and reapplied during rebuilds.
- World patches are assigned to the visible contributing reference; new entities
  use the nearest local reference footprint. Overlapping/ambiguous additions may
  need source editing instead. This is approximate ownership, not an ID system.
- Stitching a patch edits the selected template's own snapshot. Nested-reference
  override editing and stitching a whole neighbor to multiple source templates are
  not implemented. Neighbor patches can be individually discarded.
- Circuit-generated filters/scanner output and Cybersyn's generated combinator
  control behavior are excluded from change detection. Cybersyn user settings in
  metadata are compared. Wire-only changes are not separate review rows yet.
- Dragging previews ordering; Apply order performs the expensive rebuild once.
  The Factorio GUI API does not expose a reliable drag-release event, so a timeout
  must not rebuild while a person is still holding a row.
- Preview ghosts use an isolated force without construction bots. They are visual
  guides, never part of captures/commits, and are cleared when leaving the preview.
- World cell dimensions remain fixed. The initial World has four cells; Create instance adds a cell at the
  camera position on that fixed lattice. Origin/custom layout plus padding works.
- Neighbors are one group by default, expandable into whole-neighbor rows.
  Ownership is by entity center at the
  receiving cell boundary. Fine-grained neighbor overrides remain future work. Slots are one level
  deep and align committed anchor geometry; legacy position presets are hidden.
- Source is the October 24 book, not the current multiplayer save. All 20 source
  modules, including small placeholders, remain. Unsupported isolated elevated
  rails remain captureable ghosts.
- This is an editor/placement prototype, not a supplied logistics factory. Train
  operations, throughput, concurrent multiplayer edits, exotic prototype transforms,
  and production-scale performance are not certified. Native capture excludes
  trains and the default refined-concrete editor floor. Save to persist your edits.

Responsiveness pass (2026-11-01)
- UI rebuild operations use a saveable single-writer task queue, with progress in
  the action button and a progress panel. Floor work is split into 32-tile batches;
  world placement runs one blueprint layer per tick. Individual native blueprint
  builds/captures and editor composition are still synchronous engine calls, so
  very large layers can still cause a short frame spike. This is not a constant
  millisecond budget or a production-scale performance guarantee.
- Collection cards populate incrementally. Change badges use cached authoring
  diffs; script changes that do not raise build/mine/settings events refresh when
  their changes view is opened. Idle editors do not poll entire padded islands.
- Preview-only references are editor underlays, omitted from built compositions
  and physical usages. Usages follow committed references, including nested paths;
  the list describes placements, not a guarantee that every building survives
  later overlapping layers.
- Neighbors default to one contiguous priority group after The Grid and before
  own additions. The header expands individual neighbors; this is saved per cell.
  Collapsing gathers them at the first neighbor's priority. Reordering the group
  moves all its neighbors together.

Slots pass (2026-11-01)
- Slot definitions and filler eligibility are template metadata. Assignments live
  on each reference and follow normal reference commit/discard semantics.
- Anchors match entity type and align position and cardinal orientation. They are
  geometry based: commit a newly placed anchor before a slot activates; deleting
  or moving it deactivates the slot until its anchor is selected again.
- Fillers cannot contain slots, including through normal nested references.
  Filled templates must be unassigned before adding slots or disabling eligibility.
- Bay spine's imported blueprint has no train stops. It starts with three inactive
  slots. Add/select its anchor entities in the collection. Imported station
  templates with one train stop have that stop configured as their filler anchor.
- Stitching world patches on a slot-filled host is disabled: edit the appropriate
  filler source in the collection. Discard/reset remains available. Routing a
  geometric patch to an individual slot source is not implemented.
